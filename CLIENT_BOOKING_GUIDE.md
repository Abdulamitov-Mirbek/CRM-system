# DAAMDA CRM - Клиентский Портал Бронирования

## 📱 Обзор системы

Система разделена на две части:

### 1. **Admin/Staff Dashboard** (`/dashboard`, `/reservations`)
- Управление бронированиями (CRUD операции)
- Отслеживание статусов
- Управление столиками и меню
- Только для персонала кафе

### 2. **Client Booking Portal** (`/client-booking`)
- Просмотр активного бронирования
- Просмотр заказанных блюд и напитков
- Отслеживание статуса приготовления
- Нет функций редактирования
- Доступ только клиентам

---

## 🎯 Клиентский Портал: `/client-booking`

### Структура страницы

#### Заголовок
- Название: "Мое бронирование"
- ID заказа: "BOOK-2024-001"
- Текущий статус бронирования (Подтверждена / За столом / Завершена)

#### Информационные карточки (4 столбца)

**1. Время (Clock icon)**
- Время начала и конца бронирования
- Длительность в минутах

**2. Гостей (Users icon)**
- Количество гостей
- Номер столика

**3. Блюда (Utensils icon)**
- Количество готовых блюд из общего количества
- Прогресс-бар с анимацией

**4. Напитки (Wine icon)**
- Количество готовых напитков из общего количества
- Прогресс-бар с анимацией

#### Табы (3 вкладки)

**Tab 1: Блюда**
- Список всех заказанных блюд
- Информация для каждого блюда:
  - Название и описание
  - Цена и количество
  - Статус с цветовой кодировкой
  - Время приготовления (если готовится)
  - Прогресс-бар приготовления (пульсирует)
  - Иконка с текущим статусом

**Tab 2: Напитки**
- Список всех заказанных напитков
- Аналогичная информация как для блюд
- Без информации о времени приготовления

**Tab 3: Сводка**
- Общая стоимость заказа
- Разбор по позициям
- Специальные пожелания (если есть)
- Статистика по блюдам и напиткам

---

## 🔄 Статусы и их значения

### Статусы блюд/напитков:

| Статус | Иконка | Цвет | Описание |
|--------|--------|------|----------|
| **pending** (Ожидание) | AlertCircle | Желтый | Заказ принят, ожидает подтверждения |
| **preparing** (Готовится) | ChefHat | Синий | Идет процесс приготовления |
| **ready** (Готово) | CheckCircle2 | Зеленый | Готово, ожидает подачи |
| **served** (Подано) | UtensilsCrossed | Голубой | Уже подано клиенту |

### Статусы бронирования:

| Статус | Цвет | Описание |
|--------|------|----------|
| **Confirmed** (Подтверждена) | Синий | Бронирование подтверждено, ожидание клиента |
| **Seated** (За столом) | Фиолетовый | Клиент уже сидит за столом |
| **Completed** (Завершена) | Зеленый | Бронирование завершено |

## 📊 Структура данных

### ClientBooking Interface

```typescript
interface ClientBooking {
  id: string;                          // ID бронирования
  bookingId: string;                   // Номер заказа (BOOK-XXXX-XXX)
  startTime: string;                   // Время начала (ISO 8601)
  endTime: string;                     // Время окончания (ISO 8601)
  guestCount: number;                  // Количество гостей
  tableNumber?: number;                // Номер столика (опционально)
  status: 'Confirmed' | 'Seated' | 'Completed'; // Статус бронирования
  
  // Массивы заказов
  meals: Array<{
    id: string;
    name: string;                      // "Стейк из лосося"
    description: string;               // "Филе лосося на гриле с лимонным соусом"
    price: number;                     // 850 рублей
    quantity: number;                  // 2 порции
    status: 'pending' | 'preparing' | 'ready' | 'served';
    preparationTime: number;           // Время приготовления в минутах
  }>;
  
  drinks: Array<{
    id: string;
    name: string;                      // "Красное вино - Вальпаверелла"
    description: string;
    price: number;
    quantity: number;
    status: 'pending' | 'preparing' | 'ready' | 'served';
  }>;
  
  totalAmount: number;                 // Общая стоимость (5670 рублей)
  specialRequests?: string;            // "Без лука, пожалуйста"
}
```

## 🔐 Работа процесса

### Процесс создания и отслеживания:

```
1. КЛИЕНТ БРОНИРУЕТ
   ├─ Посещает /reservations (на мобильнике или QR код)
   ├─ Заполняет форму (если нет аккаунта)
   └─ Получает ссылку /client-booking?id=XXX

2. ПЕРСОНАЛ ГОТОВИТ
   ├─ Видит заказ в /reservations
   ├─ Изменяет статус: Pending → Preparing
   ├─ Продолжает готовить...
   └─ Меняет статус: Preparing → Ready → Served

3. КЛИЕНТ ОТСЛЕЖИВАЕТ
   ├─ Видит все блюда и напитки
   ├─ Видит прогресс-бары
   ├─ Получает уведомления о статусе
   └─ Видит "Готово" когда напиток готов
```

## 📱 Использование на мобильнике

### Доступ:
1. Клиент получает SMS с ссылкой: `https://yoursite.com/client-booking?bookingId=BOOK-2024-001`
2. Открывает ссылку на мобильнике
3. Видит свой заказ в реальном времени
4. Может обновить страницу для получения свежих данных

### Преимущества:
- ✅ Нет необходимости в отдельном приложении
- ✅ Работает на любом браузере
- ✅ Полностью на русском языке
- ✅ Адаптивный дизайн для мобильных
- ✅ Реальное время обновления

## 🚀 Рабочий сценарий

### Пример: Клиент приходит на обед

```
15:00 - Клиент прибывает в кафе
    ├─ Подтверждение: Статус = "Подтверждена"
    
15:05 - Клиент садится, заказывает еду и напитки
    ├─ Блюдо #1: Статус = "Ожидание"
    ├─ Напиток #1: Статус = "Ожидание"
    └─ Клиент видит на телефоне: "Ожидание"
    
15:10 - Персонал принимает заказ
    ├─ Меняет статус: "Ожидание" → "Готовится"
    └─ Клиент видит на телефоне: "Готовится" с таймером
    
15:15 - Напиток готов
    ├─ Меняет статус: "Готовится" → "Готово"
    └─ Напиток подается
    ├─ Меняет статус: "Готово" → "Подано"
    └─ Клиент видит: "Подано" ✓
    
15:20 - Блюдо готово
    ├─ Меняет статус: "Готовится" → "Готово"
    ├─ Блюдо подается
    ├─ Меняет статус: "Готово" → "Подано"
    └─ Клиент видит: "Подано" ✓
    
15:50 - Клиент заканчивает есть
    ├─ Персонал меняет статус всех: "Подано" → "Готово" (Завершено)
    └─ Клиент видит статус: "Завершена"
```
